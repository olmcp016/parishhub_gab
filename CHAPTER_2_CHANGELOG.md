# Chapter 2 Changelog

This log records every change applied to `CHAPTER_2_REVISED.docx` (a copy of `CHECKED_BAYO.docx`), why each change was made, and the code evidence behind it. Full detail and the complete gap analysis are in `CHAPTER_2_REVISION_REPORT.md`. Chapters 1 and 3 and all content outside Chapter 2 were verified byte-identical to the original and were not touched.

## System Rules (narrative)

1. **Added staff/priest login portal note (¶126).** Appended a sentence noting registered parishioners sign in through the parishioner login while staff and priests use a separate staff and priest portal. *Why:* `staff/login.php` is a real, separate login page from `auth/login.php`; the manuscript described only one shared login.
2. **Added email-verification step (¶127).** Inserted a sentence requiring the parishioner to verify their email before logging in. *Why:* `auth/register.php` sends a verification link and `auth/login.php` blocks unverified accounts; this step was missing.
3. **Rewrote the funeral/wake/blessing/priest-preference passage (¶128).** Replaced the "Misa sa Lubong / Misa sa Haya ug Misa sa Sementeryo," nine-day-wait, fixed-1:00-PM description with the real model (Funeral, Wake Mass, or Special Mass Request; any date after death; no fixed time). Added the previously undocumented Anointing of the Sick and Certificate Request services, and the "outside priest" option. *Why:* `includes/scheduling.php` explicitly comments "No waiting period and no fixed time"; the two named funeral options no longer exist in the service catalog.
4. **Corrected Mass intention times (¶133).** Replaced "6:00 AM Mon–Sat; 6:00/9:00/4:00 Sun" with the real schedule (6:00 AM Mon/Tue/Thu/Fri/Sat; 5:15 PM Wed; 6:30/9:00/4:30 PM Sun). *Why:* `includes/scheduling.php`'s `MASS_INTENTION_TIMES` constant.
5. **Resolved the Mass-intention donation rule (¶133).** Removed the author's own bracketed uncertainty ("need pag data or 0 jud?") and confirmed the rule is strictly greater than ₱0.00, adding the previously undocumented ₱1,000,000 cap. *Why:* `parishioner/book.php:290-294` enforces `offeringAmount > 0 && offeringAmount <= 1000000` server-side. This was the audit's explicitly flagged question.
6. **Reversed the auto-cancellation claim (¶135).** Changed "is automatically cancelled" to "is not automatically cancelled... notified... should be rescheduled." *Why:* `includes/functions.php`'s own code comment states approved appointments are deliberately never auto-cancelled; the function only notifies.
7. **Corrected donation purposes (¶136).** Removed "General Donation" (does not exist in code) and replaced the purpose list with the real `DONATION_PURPOSES` (Church Maintenance, Charity, Mass/Parish Activities, Other/Not Specified). *Why:* `includes/functions.php:737-738`.
8. **Corrected announcement image count (¶138).** Changed "an optional image" to "up to three optional images." *Why:* `migration_announcement_images.sql` added `image2`/`image3`.
9. **Expanded the security paragraph (¶140).** Appended a sentence on mandatory email verification, login-attempt lockout, administrator-forced password change, and OTP-based self-service password reset. *Why:* `auth/login.php`, `auth/forgot-password.php`, `auth/force_change_password.php`, backed by `migration_auth_throttle.sql`, `migration_must_change_password.sql`, `migration_password_reset_otp.sql` — none of this was previously documented.

## Process Specification

10. **Rewrote Process 30 (Automatic Cancellation Process).** Replaced "Set status to Cancelled / Notify parishioner" with "Notify the secretary and the parishioner or guest... / Preserve the appointment, priest reservation, and documents (do not change the status)." *Why:* same code evidence as item 6. The edit was carefully scoped to Process 30 only — the same phrase "Set status to Cancelled" also appears, correctly, in Process 11 (parishioner self-cancellation), which was verified untouched.

## Database Design

11. **Table 4 (Users):** added `verification_token`, `token_expires_at`, `must_change_password` columns. *Why:* `migration_email_verification.sql`, `migration_must_change_password.sql`.
12. **Table 8 (Services):** corrected the `category` enum from 8 values to the real 11 (added Wake, Anointing, Certificate). *Why:* `migration_anointing.sql`, `migration_certificate_request.sql`.
13. **Table 13 (Appointments):** added 11 missing columns — `precana_type`, `precana_date`, `precana_time`, `precana_status`, `outside_priest_name`, `requester_name`, `patient_name`, `preferred_burial_date`, `preferred_burial_time`, `payment_deadline`, `requirements_review_status`, `revision_requested_at`. *Why:* the single largest schema gap found; see `migration_precana.sql`, `migration_outside_priest.sql`, `migration_anointing.sql`, `migration_funeral_preferred_burial.sql`, `migration_payment_deadline.sql`, `migration_requirements_review.sql`.
14. **Table 17 (Uploaded_documents):** removed the `baptism_draft_id` row (column was dropped) and corrected `draft_id`'s description to reflect the unified `Appointment_drafts` table. *Why:* `migration_merge_drafts.sql`.
15. **Table 25 (Announcements):** added `image2`, `image3` columns and corrected `image`'s description to "First (cover) image." *Why:* same evidence as item 8.
16. **Table 30 (Notifications):** added the `appointment_id` column. *Why:* `migration_notifications_v2.sql`.

## What was deliberately NOT changed in this pass (see `CHAPTER_2_MANUAL_CHECKLIST.md`)

- **Tables 18–21** (Generated_wedding_forms / Generated_baptism_forms / Wedding_booking_drafts / Baptism_booking_drafts) are now structurally obsolete (merged into `Generated_forms` and `Appointment_drafts`), but were **not** restructured or renumbered in this pass — doing so safely requires either careful table deletion/insertion or a renumbering decision that affects every subsequent table reference, and was judged too high-risk to perform as blind text surgery without a visual/editorial review. Flagged in the manual checklist.
- **Five undocumented tables** (`auth_throttle`, `password_reset_otps`, `email_logs`, `app_sessions`, `issued_certificates`) were identified but not inserted as new Word tables in this pass, for the same reason — adding whole new tables with correct formatting/numbering is safer done with visual confirmation. Flagged in the manual checklist.
- **Figure 10, Figures 11–32, and Figure 39** (Context Diagram, Event List Diagram, Database Schema/ERD) were **not** regenerated — no up-to-date diagram source exists in the repository (see the revision report §3), and diagrams cannot be safely edited as text. Flagged in the manual checklist.
- **Event List items 23–24** (Certificate Request/Release, Password Reset) and the corresponding **Process Specification items** (Certificate Request Process, Forgot Password Process, split Login Process, revised Service Booking Process) were documented as recommended additions in the revision report but **not yet inserted** into the manuscript body in this pass, to keep the scope of blind text-surgery edits to the highest-confidence, most load-bearing corrections (the ones directly contradicted by code, or explicitly flagged by the author). Flagged in the manual checklist as a recommended follow-up pass.
- **Test Data/Cases, Revision of the System, Technical Requirements, Cost-Benefit Analysis, and Interface Design** sections were reviewed (see the revision report §2.6) but left unchanged except where noted above — no factual errors were found that warranted a text change beyond what the report flags for confirmation.
- The **Present System** section (System Narrative, Constraints, Event List) was reviewed and left completely unchanged — it describes the manual process, which the audit confirmed is not contradicted by anything in the codebase.
